# 动态出题引擎设计文档

> 日期：2026-08-11
> 项目：传统医学出师考核一站式学习工具（`D:\Work\syllabus\`）
> 状态：已与用户确认（含错题本、动态题详解联动、分批次实施计划）

## 一、背景与问题

用户反馈：以中医基础理论（`s1-zhongji.js`）为例，练习题每次抽到的都是做过的题，已能背诵，反复练习失去意义。出题缺乏**随机性与新鲜感**。

根因分析：

- 题库主要来自两处：科目文件中的静态题数组（中基约 63 道）+ 卡片自带的 `cardQuiz` 随学随练（中基 32 道）。
- 出题逻辑（`app.js` 的 `startQuiz`）按正确率三池（复习 60% / 巩固 30% / 探索 10%）加权随机抽取。
- 题池总量有限，60-80 题的大卷必然高度重复。

而知识卡片中含有大量未被利用的"富矿"：

- 142 个知识点，每个都有 `content`（HTML），多数卡片含经典原文（`.classic-quote`）、通俗理解（`.plain`）、助记口诀（`.mnem`）等结构化块（口径：助记口诀 96 处、derive-box 推导步骤 125 处、归纳总结 `.kv` 若干）。
- 这些结构化内容可自动生成**质量可控且可无限变化**的新题。

## 二、目标与方向（已确认）

- **出题方式**：运行时动态出题（新增独立模块 `dynquiz.js`，作为"动态出题引擎"，现场从卡片内容组装新题），而非脚本批量预生成。一次开发全科目通用。
- **去重策略**：全局去重 + 结合正确率降权。没见过的题优先出；做过的按熟练度降权，越熟越少出现。
- **题型范围**：尽量多样。在现有单选/填空/连线基础上，新增"口诀挖空"、"原文接龙/出处匹配"等题型。

## 三、整体架构

新增独立模块 `dynquiz.js`，作为"第三类题源"接入现有出题流程。

现有流程（保持骨架不变）：

```
startQuiz() → 三池加权抽题 → showQuiz() 渲染 → _submitQuiz() 判分
```

改动点：

1. **出题时**：`startQuiz()` 不再只从静态题库 `questionBank` 抽题，而是调用 `DynQuiz.generate(subjects, count)`，现场从知识卡片内容组装一批动态题，与静态题**混合出卷**。**建议混合比例**：动态题占 70%、静态题占 30%（静态题作为高质量基础题源保底）；出题时两类分别按去重权重/三池逻辑选出后合并、整体乱序。
2. **判分渲染**：动态题完全复用现有题目格式（`choice` / `fill` / `match`），渲染和判分代码零改动。动态题仅额外携带 `dyn:true` 标记与题签名 `sig`，用于去重记录。

复用现有格式带来的红利：

- `_submitQuiz` 判分逻辑自动适用。
- `quizHistory` 做题记录自动适用。
- `savePerf(pointId, correct)` 正确率统计自动适用（动态题同样携带 `pointId`）。
- 复习标签（新题/重点复习/掌握）自动适用。

`index.html` 脚本加载顺序：`app.js` → `dynquiz.js` → `xlink.js` → `mini-quiz-patch.js` → 科目文件 → `practical-exam.js`。引擎在出题时才读取已注册的科目数据，加载顺序宽松。

## 四、出题引擎：如何从卡片"变"出题

引擎扫描选定科目所有知识点的卡片 `content`（HTML 字符串），用正则提取结构化块并剥离标签取纯文本，按题型现场组装。每道题计算唯一**题签名**，供去重使用。

### 4.1 题型生成器

| 题型 | 现有格式 | 素材来源 | 说明 |
|------|---------|---------|------|
| 概念辨析型 | `choice` | 卡片说明段 `<p>` 真实表述 | 给四个真实表述选属于该知识点的（正确项=本卡 `<p>` 概念句，干扰项=其他卡 `<p>` 表述，优先同单元）。考"哪个内容属于该知识点"，素材来自说明而非口诀；剔除复述点名/方剂/临床/编号片段 |
| 原文理解型 | `choice` | `.classic-quote` 引号内原文句 | 给经典原文选其阐释的概念（正确项=本知识点名）。**替代旧"概念要点"**：用知识点名作答，从根本上杜绝方剂/中药名混入；跨卡重复原文跳过避免歧义 |
| 出处匹配 | `choice` | `.classic-quote` 内 `.src` 出处 | 问"出自哪部经典"，题面取引号内原文句、剥离 `《书名》：` 前缀；出处前导破折号（em-dash U+2014）已清理；干扰项取其他出处 |
| 原文接龙 | `choice` | `.classic-quote` 引号内原文句（≤24 字） | 给上半句选下半句；**仅取≤24字经典短句**减量提质；干扰项取其他卡片句子的下半句 |

**题型配比**（v3，已实施）：概念辨析型 30% / 原文理解型 30% / 出处匹配 25% / 原文接龙 15%。原文接龙由 v1 的约 45% 降至 15%。

**单元分层加权**（v2，已实施）：动态题按单元重要度加权抽样--第五~八单元（五脏/六腑/奇恒之腑/气血津液）权重 3，第三/四/十二单元（阴阳/五行/病机）权重 2，其余权重 1。实测 5-8 单元题量约占 60%。

> **实测口径**（s1 中基，142 知识点）：`.mnem` 96 处、`.classic-quote` 117 处（含 36 种不同出处）、引号内原文句 151 个（其中跨卡重复 16 个，原文理解型跳过；可拆分≤24字短句 104 个）。v1 曾用 `<strong>` 短术语做"概念要点"，但脏器等卡片的概念词不在 `<strong>`、且病机卡片的"代表方"段落会把方剂名（黄连解毒汤等）误当概念，故 v2 改为"原文理解型"用知识点名作答，彻底规避此问题。v2 的"口诀理解型"（给口诀选知识点）因口诀含器官名易被关键词匹配、且照搬口诀未考理解，v3 改为"概念辨析型"--从卡片说明段 `<p>` 抽真实概念表述作答，考内容识别而非口诀匹配。

### 4.2 生成规则

- 每种生成器带"内容过短即跳过"保护，避免挖出单字空或残缺句。
- 挖空答案优先取口诀中的中医药关键词（二至三字成词），保证有意义。
- 单选干扰项优先取**同单元其他卡片**的同类句子，再不够就从其他科目借，保证干扰项"像真的"。
- 卡片自带 `cardQuiz` 与科目静态题继续保留在题池中，作为高质量基础题源。

## 五、去重与降权（"不重复"核心）

### 5.1 记录（批次2已实施）

每次判分时，`app.js` 的 `_submitQuiz` 对动态题（`q.dyn && q.sig`）调用 `DynQuiz.recordResult(sig, correct)`，将其记入 `dynHistory`（localStorage，key=`dynHistory`，对象结构）。每条记录含 `count`/`correct`/`consecCorrect`/`lastCorrect`/`lastSeen`，软上限 2000 条。签名基于：

```
签名 = hash(知识点ID + "|" + 题型 + "|" + 问句)
```

同一知识点不同问法 → 不同签名 → 各自独立去重。题签名用简单字符串 hash，不引入加密库。

### 5.2 出题排序（优先级从高到低）

1. **全新题**（从未做过）优先出，保证新鲜感。
2. **做过但错的题**——"没掌握"要多练。
3. **做过且对的题**——正确次数越多，权重越低。
4. **做过多次且全对的熟题**——基本不再出，除非该知识点题源枯竭。

### 5.3 降权权重（批次2已实施）

权重与单元重要度相乘后用于加权抽样（combinedWeight = unitWeight × dynWeight）。

| 状态 | dynWeight |
|------|------|
| 从未见过 | 20 |
| 上次答错（无论次数） | 16 |
| 连续答对 1 次 | 6 |
| 连续答对 2 次 | 3 |
| 连续答对 3 次以上 | 1（几乎不再出现） |

> 实测：第1轮60题全答对后，第2轮60题100%为全新题（做对题降权生效）；50道熟题+50道错题同池抽样，熟题仅2道、错题6道出现（错题多练、熟题淘汰）。`consecCorrect` 连对计数，答错即清零。

### 5.4 多问法轮换

签名精确到"问法"级别。同一知识点第一次挖 A 词、下次挖 B 词，签名不同，算新题。一个知识点可变化出多道互不重复的题。

### 5.5 范围

去重只作用于动态题。静态题（63 道 + cardQuiz）保持原样，做几轮后会被引擎自然淘汰出局（变"熟题"权重极低），动态题持续供应新鲜感。

## 六、交互界面

- 现有"重新出题 🔄"按钮直接复用——每次点击重新调用引擎生成新卷。
- `showQuizSetup()` 科目选择区加一行说明："动态出题：基于知识卡片实时生成新题，做过的题自动降权。"
- 题目卡片上加小标签"✨ 动态"（区别于静态题）。

## 七、性能

- 出题只扫描**选中的科目**，不扫描全部九个科目。
- 卡片 `content` 提取在内存中一次性完成。142 张卡片、约 300KB 文本，纯 JS 解析并组装 60 题，预计 **50ms 以内**，无感。
- 题签名用简单字符串 hash。

## 八、错题本

### 8.1 目标

把做错过的题集中管理，便于回顾巩固，与动态出题的降权机制配合形成"做错→记入错题本→反复练习→掌握"闭环。

### 8.2 数据记录

在 `quizHistory`（做题记录）的基础上，新增 `wrongBook`（localStorage 数组）。每次判分时，将**答错**的题记入错题本，结构：

```
{
  sig: "题签名(动态题)/题id(静态题)",
  type: "choice|fill|match",
  pointId: "知识点ID",
  question: "题干",
  options: [...],        // choice 题才需要
  answer: "...",         // 正确选项/填空答案/match键值
  explanation: "解析",
  wrongCount: 1,         // 答错次数
  lastWrong: "时间戳",
  resolved: false        // 是否已掌握（连续答对2次标记true）
}
```

- 同一题再次答错 → `wrongCount` 累加、`lastWrong` 更新。
- 同一题在错题本中连续答对 2 次 → 自动标记 `resolved:true`，移出"待复习"列表（记录仍保留）。

### 8.3 交互

- 新增"错题本"入口：可在 `showQuizSetup()` 页面加一个按钮，或在底部 Tab 栏加一个"错题"标签（与"做题记录"并列）。
- 错题本页面列出所有未掌握错题（`resolved:false`），显示题干、类型、所属知识点、答错次数、上次答错时间。
- 每题提供"📖 查看知识点"链接（跳转到知识卡片）与"📝 再练一次"按钮。
- "再练一次"按钮将单题放入 `currentQuiz`，复用现有判分/渲染逻辑。
- 支持手动"标记为已掌握"（用户自评已掌握，无需等连续答对 2 次）与"清空错题本"操作。
- 错题本与动态出题联动：动态出题时，来源知识点存在未掌握错题的**动态题**会提升权重优先出现。**静态题**无需额外联动——答错后正确率下降，已自动进入现有三池逻辑的复习池（`rate<0.5`）。

## 九、动态题详解联动

### 9.1 目标

动态题由卡片内容实时生成，判分后自动显示关联知识卡片内容作为解析，解决"动态题没有配套解析"的问题。

### 9.2 设计

- 动态题生成时自动携带 `explanation` 字段，取**来源卡片**的 `.plain`（通俗理解）或 `.kv`（归纳总结）纯文本摘要。
- 渲染时复用现有 `q.explanation || q.expl || '（暂无解析）'` 逻辑，动态题默认有解析。
- 每题已有的"📖 知识点"链接（`_showCardFromQuiz(pointId)`）保持不变，点击跳转到完整知识卡片。
- 口诀挖空题额外在解析中展示**完整口诀**（`q.fullMnem`），便于核对。
- 静态题维持原有解析来源（`expl` 字段），不在此次改造范围。

## 十二、技术风险与规避

- `app.js` 为 66KB 大文件：**任何修改必须用 Python via bash**（读→替换→写回），禁用 Write/Edit 工具。修改后必跑 `node --check` 验证语法。
- 新增文件 `dynquiz.js` 若超 20KB，同样用 Python heredoc 写入，避免 Write 工具截断。
- 卡片 `content` 为正则抽取，需对中文标点（书名号、括号）做转义测试。
- 错题本与 `dynHistory` 均存 localStorage，需控制数组长度上限（如各 500 条），避免超出存储配额。
