## 二、中药学derive-box结构设计

### 2.1 药类型derive-box（各论第5-21单元）

适用于单味药或一组同类药的知识点。核心回答：**为什么选这味药？**

**derive-flow骨架**：
```
病证表现(df-symptom) → 药性需求(df-concept) → 功效匹配(df-logic) → 选定药物(df-organ)
```

**derive-step三层**：

| 步骤 | 标题范式 | 内容 | CSS |
|------|---------|------|-----|
| 1 | 药性推导：从病证到选药的逻辑链条 | 150-200字。展示：病证表现→需要什么药性（四气五味归经升降浮沉）→这味药的性味归经如何恰好对应。回答"为什么这个病证需要这味药"。 | ds-blue |
| 2 | 类药鉴别：为什么选A不选B | 200-300字。同类药中横向对比：功效异同、主治差异、用法区别。不仅要列出区别，更要解释"为什么会有这些区别"（药性基础决定功效差异）。 | ds-purple |
| 3 | 跨科闭环：药→方→证的完整链条 | 100-150字。这味药在哪些方剂中使用？每个方中扮演什么角色（君臣佐使）？这些方治什么证？在中诊中如何辨证？形成药-方-证的推导闭环。 | ds-red |

### 2.2 示例：麻黄（zy-10-1）derive-box

```html
<div class=derive-box>
  <div class=derive-flow>
    <span class="df-node df-symptom">恶寒发热无汗<br>脉浮紧</span>
    <span class=df-arrow>→</span>
    <span class="df-node df-concept">辛温发散<br>归肺膀胱</span>
    <span class=df-arrow>→</span>
    <span class="df-node df-logic">发汗解表<br>宣肺平喘</span>
    <span class=df-arrow>→</span>
    <span class="df-node df-organ">麻黄</span>
  </div>

  <div class="derive-step ds-blue">
    <span class=ds-num>1</span>
    <span class=ds-title>药性推导：从病证到选药的逻辑链条</span>
    <div class=ds-body>
      <strong>病证：</strong>风寒表实证——恶寒发热，无汗，头身疼痛，脉浮紧。<br>
      <strong>病机：</strong>风寒束表，卫阳被遏，营阴郁滞，毛窍闭塞。<br>
      <strong>药性需求：</strong>需要辛温之品发散风寒(辛能散、温能祛寒)；需要归肺经以宣通肺气(肺主皮毛)；需要走表以开腠理(发散表邪)。<br>
      <strong>麻黄恰好满足：</strong>辛微苦温→辛散温通发散风寒；归肺膀胱经→入肺宣肺、入膀胱通阳利水。麻黄"开腠理"的发汗力在解表药中最强，专攻表实无汗——药性与病机精准对应。
    </div>
  </div>

  <div class="derive-step ds-purple">
    <span class=ds-num>2</span>
    <span class=ds-title>类药鉴别：为什么选麻黄而不选桂枝/紫苏</span>
    <div class=ds-body>
      <strong>麻黄 vs 桂枝：</strong>两者都辛温解表，但麻黄发汗力强(开腠理)→专治表实无汗(麻黄汤君药)；桂枝发汗力缓(解肌)→专治表虚有汗(桂枝汤君药)。差异根源在于：麻黄为草质茎，质地轻扬，发散力峻猛；桂枝为嫩枝，温通为主，发散力温和。<br>
      <strong>麻黄 vs 紫苏：</strong>麻黄发汗力强专攻表实证；紫苏发汗力弱兼行气宽中→适用于外感风寒轻证兼气滞胸闷者。紫苏还能解鱼蟹毒——麻黄无此功效。<br>
      <strong>选药口诀：</strong>无汗用麻黄，有汗用桂枝，胸闷用紫苏。三者同属辛温解表，但发汗强度递减(麻黄＞桂枝＞紫苏)，兼有功效各不同。
    </div>
  </div>

  <div class="derive-step ds-red">
    <span class=ds-num>3</span>
    <span class=ds-title>跨科闭环：药→方→证的完整链条</span>
    <div class=ds-body>
      <strong>方剂学：</strong>麻黄→麻黄汤[fj-2-1]治风寒表实(君药·发汗解表)→麻杏甘石汤[fj-2-4]治肺热咳喘(君药·宣肺平喘，石膏倍麻黄制其温性)→小青龙汤[fj-2-1]治外寒内饮(君药·解表散寒)。<br>
      <strong>中诊：</strong>→ 风寒束表证：恶寒重发热轻，无汗，脉浮紧，苔薄白。<br>
      <strong>闭环：</strong>中诊确认风寒表实→方剂以麻黄为君组方(麻黄汤)→中药麻黄辛温解表恰好对应病证需求。同一味麻黄在不同方中"药随方变"——配桂枝则发汗、配石膏则清肺、配干姜细辛则化饮。
    </div>
  </div>
</div>
```

## 三、与方剂学derive-box的互补关系

方剂学从**方拆药**（证→法→方 / 方→药→量 / 跨科串联），中药学从**药连方**（病证→药性→选药 / 类药鉴别 / 药→方→证）。

| 维度 | 方剂学derive-box | 中药学derive-box |
|------|-----------------|-----------------|
| 推导起点 | 证候表现 | 病证表现 |
| 推导终点 | 方剂选择 | 药物选择 |
| 层二核心 | 君臣佐使配伍逻辑+用量密码 | 类药功效对比+选药鉴别 |
| 层三方向 | 中诊←中药→方剂（方为中心） | 药→方→证（药为中心） |
| 两者关系 | 自上而下组装 | 自下而上溯源 |

学习者在方剂学中看到"麻黄汤为什么用麻黄为君"，在中药学中看到"麻黄为什么被选入麻黄汤为君"——同一知识从两个角度互相印证。

## 五、技术风险与规避

以下问题来自S4方剂学升级中反复验证的经验，S3升级同样适用。

### ⚠️ 问题 1：文件截断
**现象**：Write 工具写入超过 ~25KB 的 JS 文件会被截断。
**规避**：全程使用 **Python 脚本 + bash heredoc** 方式写入。S3当前275KB，升级后约340KB，远超Write限制。

### ⚠️ 问题 2：单元间逗号缺失
**现象**：替换内容后单元间逗号丢失导致JS语法错误。
**规避**：S3使用单引号格式 `]}]},{unit:'` ，每次替换后修复：
```python
content = content.replace("]}]}{unit:'", "]}]},{unit:'")
```

### ⚠️ 问题 3：JS 字符串中的单引号冲突
**现象**：S3内容字符串使用单引号包裹，derive-box内部出现 `'` 会提前结束字符串。
**规避**：derive-box内容中避免使用单引号，全部使用双引号或省略。Python三引号包裹构建字符串。

### ⚠️ 问题 4：跨行 content 字符串
**现象**：JS 字符串不能物理跨行。
**规避**：Python 构建时将整个 content 压缩为一行，替换掉物理换行符。

### ⚠️ 问题 5：语法验证（强制）
**现象**：语法错误导致科目消失。
**规避**：每批次后执行 `node --check`，通过才继续。

### ⚠️ 问题 6：内容只能做加法
derive-box **新增**在 content 开头（经典原文之前），现有内容一字不减。

## 六、实现方案

### 6.1 内容插入位置

derive-box 插入在 `content` 字段最前面，在经典原文之前：
```
content:'<div class=derive-box>...</div><div class=classic-quote>...</div><p>...正文...</p>...'
```

### 6.2 实现策略

Python 脚本 + bash 执行。每个 derive-box 在 Python 中构建为字符串，使用三引号包裹避免单引号冲突，通过正则匹配知识点ID和name定位插入位置。

## 八、质量标准

每个 derive-box 必须满足：
1. **药性推导有据**：层一必须有病证→药性需求→药物匹配的完整推理
2. **类药鉴别有深度**：层二不仅要列区别，更要解释"为什么会有这些区别"
3. **跨科闭环完整**：层三必须形成药→方→证的推导闭环，引用方剂学ID
4. **语法零错误**：每批次后 `node --check` 必须通过
5. **内容不缩水**：只做加法不做减法，现有内容一字不减
