## 二、方剂学derive-box结构设计（三层逻辑链）

### 2.1 核心结构

方剂学的derive-box与内科不同——内科是"疾病推理链"，方剂学是"方剂推导链"，聚焦于**为什么选这个方、为什么用这些药、为什么是这个量**。

**derive-flow骨架**：
```
证候表现(df-symptom) → 病机核心(df-concept) → 治法(df-logic) → 选方(df-organ)
```

**derive-step三层**：

| 步骤 | 标题范式 | 内容 | CSS |
|------|---------|------|-----|
| 1 | 证→法→方：从辨证到选方的完整路径 | 150-200字。展示：主症+舌脉→辨证结论→病机概括→治法→为什么选此方（而非其他相似方）。类比：这是"诊断报告→治疗方案→处方"的临床思维链条。 | ds-blue |
| 2 | 方→药→量：君臣佐使的配伍逻辑与用量密码 | 200-300字。逐一分析：君药为什么是这味（药证对应）、臣药为什么辅助（药对逻辑）、佐药解决什么问题（制约/增效/引经）、使药调和什么。重点解释用量比例（如麻黄9g:桂枝6g为什么不是反过来）。 | ds-purple |
| 3 | 跨科串联：方-药-证的完整闭环 | 100-150字。中诊链接（→对应证型及辨证要点）、中药链接（方中每味药→中药学性味归经功效）。形成"中诊告诉你这是什么证→中药告诉你每味药能干什么→方剂告诉你为什么这样组合"的闭环。 | ds-red |

### 2.2 示例：麻黄汤derive-box

```html
<div class=derive-box>
  <div class=derive-flow>
    <span class="df-node df-symptom">恶寒发热无汗<br>脉浮紧</span>
    <span class=df-arrow>→</span>
    <span class="df-node df-concept">风寒束表<br>卫阳被遏</span>
    <span class=df-arrow>→</span>
    <span class="df-node df-logic">发汗解表<br>宣肺平喘</span>
    <span class=df-arrow>→</span>
    <span class="df-node df-organ">麻黄汤</span>
  </div>
  
  <div class="derive-step ds-blue">
    <span class=ds-num>1</span>
    <span class=ds-title>证→法→方：从辨证到选方的完整路径</span>
    <div class=ds-body>
      <strong>主症：</strong>恶寒发热，无汗，头身疼痛，气喘，脉浮紧。<br>
      <strong>辨证结论：</strong>外感风寒表实证——风寒之邪束表，卫阳被遏，营阴郁滞，毛窍闭塞。<br>
      <strong>治法：</strong>发汗解表，宣肺平喘（汗法）。<br>
      <strong>选方逻辑：</strong>表实无汗，非麻黄不能开腠理发汗；肺气不宣而喘，需宣降并用。桂枝汤治表虚有汗（营卫不和），此证无汗，故不用桂枝汤而用麻黄汤——鉴别点在于"无汗"二字。
    </div>
  </div>
  
  <div class="derive-step ds-purple">
    <span class=ds-num>2</span>
    <span class=ds-title>方→药→量：君臣佐使的配伍逻辑与用量密码</span>
    <div class=ds-body>
      <strong>君·麻黄 9g：</strong>辛温入肺膀胱，发汗解表力专——直捣卫阳被遏之病所。用量9g为君，取其发汗之力而不致过汗伤正。<br>
      <strong>臣·桂枝 6g：</strong>辛甘温，助麻黄发汗解肌。用量6g为臣，臣不超君——若桂枝反超麻黄，则发汗之力太峻且配伍重心偏移。<br>
      <strong>佐·杏仁 9g：</strong>苦微温，降肺气平喘。麻黄宣肺（向外向上）、杏仁降肺（向内向下），一宣一降恢复肺气宣肃。用量与麻黄等量（9g），宣降平衡。<br>
      <strong>使·炙甘草 3g：</strong>甘平，调和诸药，缓麻黄桂枝峻烈之性。用量3g为调和之度，过则甘缓碍汗。<br>
      <strong>用量密码：</strong>麻黄9:桂枝6:杏仁9:甘草3——君药量最大（9g），臣药不超君（6g），佐药与君等量平衡宣降（9g），使药轻量调和（3g）。
    </div>
  </div>
  
  <div class="derive-step ds-red">
    <span class=ds-num>3</span>
    <span class=ds-title>跨科串联：方-药-证的完整闭环</span>
    <div class=ds-body>
      <strong>中诊：</strong>→ 风寒束表证（表寒证）：恶寒重发热轻，无汗，脉浮紧，苔薄白。<br>
      <strong>中药：</strong>麻黄[zy-5-1] 辛温解表·归肺膀胱 | 桂枝[zy-5-2] 辛甘温·归心肺膀胱 | 杏仁[zy-13-1] 苦微温·归肺大肠 | 甘草[zy-20-1] 甘平·归心肺脾胃。<br>
      <strong>闭环：</strong>中诊确认表寒实证→中药提供四味药的性味归经基础→方剂以君臣佐使配伍成方，麻黄开表为君，桂枝助汗为臣，杏仁降气为佐，甘草调和为使。
    </div>
  </div>
</div>
```

### 2.3 概念型derive-box（总论单元）

总论三个知识点（八法、君臣佐使、剂型）不适用三层推导链，改用"概念展开型"：

| 步骤 | 内容 | CSS |
|------|------|-----|
| 1 | 概念溯源——经典出处与历史演变 | ds-blue |
| 2 | 核心逻辑——为什么这个原则在临床中有效 | ds-purple |
| 3 | 应用场景——这个原则在后续方剂中如何体现 | ds-red |

## 三、跨科关联实现方案

### 3.1 中诊关联

在derive-step 3中引用中诊证型，格式为：
```
→ 风寒束表证（表寒证）：恶寒重发热轻，无汗，脉浮紧
```
通过描述性文字建立关联，而非硬编码ID（因中诊ID体系为`dx-XX`，方剂为`fj-XX`，跨文件引用在纯静态SPA中不支持直接跳转）。

### 3.2 中药关联

在derive-step 3中引用中药学药物，格式为：
```
麻黄[zy-5-1] 辛温解表·归肺膀胱
```
通过`[zy-X-Y]`标记建立可识别关联，虽不支持跨文件跳转，但为后续可能的检索功能预留结构化标识。

## 四、技术风险与规避（必读）

以下问题来自前期开发中反复验证的经验总结，s4方剂学升级必须严格遵守。

### ⚠️ 问题 1：文件截断
**现象**：Write 工具写入超过 ~25KB 的 JS 文件会被截断，导致语法错误和内容丢失。s1-zhongji.js 曾因此整段丢失，JS 语法错误导致科目从大纲消失。

**规避**：所有超过 20KB 的 JS 文件必须用 **Python heredoc** 方式通过 bash 写入，绝对不要用 Write 工具写大文件。

```python
python3 << 'PYEOF'
with open("/sessions/.../mnt/syllabus/subjects/s4-fangji.js", "w", encoding="utf-8") as f:
    f.write("文件内容")
PYEOF
```

或者将脚本写入 `.py` 文件后 `python3 脚本.py` 执行。s4当前173KB，升级后约230KB，远远超出Write工具限制，**全程必须用Python脚本写入**。

### ⚠️ 问题 2：单元间逗号缺失
**现象**：替换某个单元后，前一个单元的 `]}]}` 和下一个单元的 `{unit:"..."}` 之间会丢失逗号，导致 JS 语法错误。

**规避**：每次替换后必须执行修复：
```python
content = content.replace(']}]}{unit:"', ']}]},{unit:"')
```
s4使用双引号（`{unit:"..."}`），修复模式如上。

### ⚠️ 问题 3：JS 字符串中的单引号冲突
**现象**：s4-fangji.js 使用 `content:'...'` 单引号包裹内容字符串，derive-box内部出现 `'` 会提前结束字符串，导致语法错误。

**规避**：
- derive-box 内容中避免使用单引号，必要时用 `"` 或省略
- 在 Python 脚本中构建 content 字符串时使用三引号包裹，避免 Python 层面的引号冲突
- 构建完成后用 `node --check` 验证

### ⚠️ 问题 4：跨行 content 字符串
**现象**：JS 单引号/双引号字符串不能跨行，content 必须在一行内完成。

**规避**：Python 构建 content 时，将整个 HTML 内容压缩为一行，或使用 `\n` 显式转义换行。derive-box 的 HTML 结构较复杂（嵌套 div），在 Python 中构建时需特别注意：

```python
content_str = '<div class=derive-box>...很长的HTML...</div>'
# 确保 content_str 中没有物理换行符，或全部替换为空格
content_str = content_str.replace('\n', '')
```

### ⚠️ 问题 5：语法验证（强制）
**现象**：JS 语法错误会导致整个科目从大纲消失，且难以定位错误位置。

**规避**：每次修改 s4-fangji.js 后立即执行：
```bash
node --check "/sessions/.../mnt/syllabus/subjects/s4-fangji.js"
```
验证通过后才能继续下一批次。不通过则立即排查修复。

### ⚠️ 问题 6：内容只能做加法
**规则**：知识点的内容只能做加法不能做减法。derive-box 是**新增**在 content 开头，绝不能删除或缩减现有内容（经典原文、方歌、对比表、陷阱提示、临床案例、历史典故、迷你诊室等均保留不动）。

**Why**：用户需要达到"理解"而非"知道"的程度。现有内容已经是经过多轮升级的成果，derive-box 是对"为什么"的补充，而非替代。

### ⚠️ 问题 7：输出路径
**规则**：所有最终交付文件保存到 `D:\Work\syllabus\`（对应 bash 路径 `/sessions/.../mnt/syllabus/`），不使用 C 盘默认路径。

## 五、技术实现方案

### 5.1 现有CSS支持

`index.html`中已有完整的derive-box CSS基础设施（`.derive-box`, `.derive-flow`, `.df-node`, `.derive-step`, `.ds-blue/purple/red/orange`, `.ds-num`, `.ds-title`, `.ds-body`），无需新增CSS。

### 5.2 内容插入位置

derive-box插入在`content`字段中，位于**经典原文之前**，作为方剂学习的第一眼内容：

```
content:'<div class=derive-box>...</div><div class=classic-quote>...</div><p>...方剂正文...</p>...'
```

### 5.3 实现策略

采用**Python脚本 + bash执行**方式，通过heredoc写入，规避文件截断问题（详见第四节）。

每个derive-box在Python脚本中构建，使用三引号（`'''`）包裹以避免单引号冲突（s4使用单引号字符串）。

### 5.4 批次策略

由于38个derive-box内容量较大，建议分批次执行：

| 批次 | 单元范围 | derive-box数 | 说明 |
|------|---------|-------------|------|
| 第1批 | 单元1-3（总论+解表+泻下） | 7+3 | 含概念型，建立模板 |
| 第2批 | 单元4-6（和解+清热+祛暑） | 3+4+1 | 清热剂方剂最多 |
| 第3批 | 单元7-9（温里+补益+固涩） | 2+4+2 | 补益剂重点 |
| 第4批 | 单元10-13（安神+开窍+理气+理血） | 1+1+2+3 | 理血剂方剂多 |
| 第5批 | 单元14-19（治风+治燥+祛湿+祛痰+消食+驱虫） | 2+2+2+2+2+1 | 尾部单元 |

每批完成后立即 `node --check` 验证，验证通过再进入下一批。

## 八、质量标准

每个derive-box必须满足：
1. **逻辑链完整**：证→法→方、方→药→量、跨科串联三层不缺
2. **用量有解释**：不能只说"麻黄9g"，要解释为什么是9g而不是6g或12g
3. **鉴别有对比**：layer 1 中必须回答"为什么选此方而非相似方"
4. **跨科有闭环**：layer 3 中必须形成中诊→中药→方剂的完整闭环
5. **语法零错误**：每批次完成后 `node --check` 必须通过
6. **内容不缩水**：只做加法不做减法，现有内容一字不减
