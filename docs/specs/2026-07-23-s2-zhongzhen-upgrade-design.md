## 二、derive-box 结构规范（中诊专属）

以下三种 derive-box 结构是本次改造的核心。所有结构最后必须有 ≥2 个场景变体和 ≥1 个临床案例。

### 2.1 概念展开型（用于绪论、按诊、脉诊总论等概念性知识点）

**derive-flow 骨架**：
```
概念定义(df-concept) → 核心原理(df-logic) → 临床运用(df-organ) → 诊断价值(df-symptom)
```

**derive-step 四步**：

| 步骤 | 标题范式 | 内容 | CSS |
|------|---------|------|-----|
| 1 | 为什么要做[望神/按诊/切脉]？——中医的逻辑 | 150-250 字，从"人体是一个整体"推导这个诊法存在的必要性和原理 | ds-blue |
| 2 | 核心机制：怎样从"外面"看到"里面" | 200-300 字，这个诊法的工作原理 | ds-red |
| 3 | 正常 vs 异常——从观察到判断 | 250-350 字，正常值 vs 异常值，异常值如何分类 | ds-purple |
| 4 | 同一个[诊断信号]，不同人的不同解读 | ≥2 个场景变体，覆盖年龄/体质/地域维度 | ds-orange |

### 2.2 症状推导型（用于问诊、望诊、望舌、闻诊中各症状的辨证）

**derive-flow 骨架**：
```
症状出现(df-concept) → 病机分析(df-logic) → 分型锁定(df-organ) → 鉴别+方药(df-symptom)
```

**derive-step 五步**：

| 步骤 | 标题范式 | 内容 | CSS |
|------|---------|------|-----|
| 1 | 同一个[症状]，背后可能有完全不同的故事 | 150-200 字，用日常场景引出"一个症状 ≠ 一种病因" | ds-blue |
| 2 | [症状]的病机分析——从"不舒服"看到"气机紊乱" | 200-300 字，中医如何理解这个症状的发生机制 | ds-red |
| 3 | 分型锁定——同是[症状]，不同的伴随信号指向不同的证 | 300-400 字，列出 2-4 种证型，每种有"症状关键字+方药" | ds-purple |
| 4 | 鉴别对比——最容易被误判的两种情况 | 150-250 字，两种容易混淆的证型之间的鉴别要点 | ds-orange |
| 5 | 同是[症状]，不同的人不同的病根 | ≥2 个场景变体，覆盖年龄/性别/体质/季节/地域 | ds-orange |

### 2.3 证型展开型（用于八纲、病性辨证、脏腑辨证的各个证型知识点）

**derive-flow 骨架**：
```
病因(df-concept) → 病机推导(df-logic) → 症状群(df-organ) → 关键鉴别点(df-symptom)
```

**derive-step 五步**：

| 步骤 | 标题范式 | 内容 | CSS |
|------|---------|------|-----|
| 1 | [证型名]到底是什么状态？——不是简单的"虚"或"实" | 150-250 字，用生活化比喻解释这个证型的本质 | ds-blue |
| 2 | 病机推导：怎样一步步走到[这个证]的 | 200-300 字，从病因→病理变化→关键症状的因果链 | ds-red |
| 3 | 症状群识别——看到什么信号就能锁定它 | 250-350 字，核心症状+鉴别症状+舌脉（关键信号用 strong 标记） | ds-purple |
| 4 | 最容易和[证型A]混淆的是什么——鉴别表 | 200-300 字，与最相似证型的鉴别（症状·舌·脉·方药的不同） | ds-orange |
| 5 | 同是这个证，不同的人表现不同——场景变体 | ≥2 个场景变体，覆盖年龄/性别/体质/基础病 | ds-orange |

## 九、B/C 批次技术复盘（2026-07-24 更新）

以下四个问题在 B/C 批次实施中反复出现，消耗了大量时间。总结原因和修复方案，作为后续 D-J 批次的操作规范。

### 问题 1：原有内容被清除（compare-table/trap-box/clinical-case 丢失）

**现象**：升级后知识点只有 derive-box 推导链，原有的 compare-table、trap-box、clinical-case 全部消失。

**根因**：设计文件第三节要求"保留现有优质元素"，但实际操作中 content txt 文件只写了 derive-box 部分，替换脚本用新 content 完全覆盖了旧 content，没有把原有尾部追加回去。

**修复**：写补丁脚本从 `.bak` 备份中提取每个知识点的原始 compare-table/trap-box/clinical-case 尾部，追加到当前 content 末尾。

**教训**：每个 txt 文件必须包含：`<p>概括 → classic-quote → mnem → derive-box → 原始 compare-table → 原始 trap-box → 原始 clinical-case`。写文件时不能只写 derive-box。

### 问题 2：多个知识点内容完全相同

**现象**：dx-32-1/dx-32-2（气虚/气陷）、dx-34-1/dx-34-2（气滞/气逆）、dx-35-1/2/3（血瘀/血热/血寒）各自组内 content 一致。

**根因**：延续了 S1 的"多知识点共用一个 txt 文件"模式。但中诊每个知识点有独立的 name 和 content，必须一对一映射。

**修复**：为每个知识点创建独立的 txt 文件，替换脚本中一一对应。

**教训**：中诊不适用 S1 的"共用文件"模式。每个知识点必须有独立文件。

### 问题 3：UTF-8 编码截断

**现象**：`node -c` 报"Invalid or unexpected token"但无法定位具体字符。python 检查后发现 txt 文件末尾的中文字符被截断。

**根因**：长 HTML 内容在 Write 工具传输/存储时，可能在中文字符的 3 字节序列中间截断。

**修复**：用 `errors='replace'` 重新解码截断文件后重写。

**教训**：每次写入 content txt 文件后，立即用 python 做 UTF-8 完整性检查。

### 问题 4：derive-box 自身 div 不平衡

**现象**：多个点出现 div opens > closes，差值恰好为 3。

**根因**：derive-step 结构为 `<div class="derive-step ds-XXX"><span class="ds-num">N</span><span class="ds-title">...</span><div class="ds-body">...</div></div>`——每次漏掉最后的 `</div>`（关闭 derive-step），一个 derive-box 有 3 个 derive-step 就缺 3 个 div。

**修复**：补入缺失的 `</div>` 数量。

**教训**：写完每个 txt 文件立即用 `grep -c` 统计 `<div` 和 `</div>` 差值，差值必须为 0。

## 十、更新后的执行策略（D-J 批次强制执行）

1. **每个知识点一个独立 txt 文件**——不共用，不合并。
